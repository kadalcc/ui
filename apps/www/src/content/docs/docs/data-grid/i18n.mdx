Every string the grid shows lives in one object, `DataGridLabels`, and every number and date goes
through `Intl` with a locale you choose. Pass a partial translation and anything you leave out
stays English.

<Demo name="data-grid-i18n" />

## Use it

```tsx
import { DataGrid, type DataGridLabels } from "@/components/ui/data-grid"

const fr: Partial<DataGridLabels> = {
  search: "Rechercher…",
  view: "Affichage",
  export: "Exporter",
  pageOf: (page, pages) => `Page ${page} sur ${pages}`,
  selected: (n) => (n === 1 ? "1 sélectionnée" : `${n} sélectionnées`),
}

<DataGrid data={rows} columns={columns} labels={fr} locale="fr-FR" />
```

Labels that carry a number are functions, so plural rules are yours. Column titles are not labels:
set `header` (or `label`) on each column in the language you want.

## Locale

`locale` is a BCP 47 tag for `Intl.NumberFormat` and `Intl.DateTimeFormat`. It defaults to the
browser's locale, which is usually right. It affects:

| Kind | Formatting |
| --- | --- |
| `number` | grouping and decimal separators; `maximumFractionDigits` defaults to 2 |
| `currency` | `style: "currency"` with the column's `currency` (default `USD`) |
| `percent` | `style: "percent"`; `maximumFractionDigits` defaults to 1 |
| `date` | `dateStyle` (default `"medium"`) |
| `datetime` | `dateStyle` + `timeStyle` (defaults `"medium"` and `"short"`) |
| `enum`, `tags` | not formatted by locale; the label comes from `options` |

The same strings appear in cells, facet filter lists, aggregated group rows, the clipboard and
exports, so they always agree. Per column, `locale` overrides the grid's (a Japanese yen column in
an otherwise German grid), and `format: (value, row) => string` replaces the formatting entirely.

```tsx
col.currency("total", { currency: "EUR" })                       // the grid's locale
col.currency("totalJpy", { currency: "JPY", locale: "ja-JP" })   // this column's own
col.date("due", { dateStyle: "full" })
col.number("score", { format: (v) => `${v.toFixed(1)} pts` })
```

Formatters are cached per locale and options, so changing `locale` at runtime is cheap.

## Dates in editors

Date and datetime editors are the browser's `<input type="date">` and `<input type="datetime-local">`,
which display and parse in the **browser's** locale, not the grid's. The value they commit is a
`Date` either way.

## Right-to-left

Set `dir="rtl"` on the document (or the grid's ancestor) as usual. Pinning uses TanStack's logical
`start` / `end` regions and CSS `inset-inline-start` / `inset-inline-end`, tree indentation uses
`margin-inline-start`, and alignment uses `text-start` / `text-end`, so a column pinned to the
start sits on the right in RTL. The “Pin to start” and “Pin to end” menu items read correctly in
both directions.

## Options

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `labels` | `Partial<DataGridLabels>` | English | Merged over the defaults. |
| `locale` | `string` | the browser's | BCP 47 tag for number and date formatting. |
| `locale` (column) | `string` | the grid's | Overrides for one column. |
| `format` (column) | `(value, row) => string` | by kind | Replaces the formatting for one column. |
| `currency` (column) | `string` | `"USD"` | ISO 4217 code for `currency` columns. |
| `dateStyle`, `timeStyle` (column) | `Intl.DateTimeFormatOptions[...]` | `"medium"`, `"short"` | For `date` and `datetime` columns. |
| `minimumFractionDigits`, `maximumFractionDigits` (column) | `number` | by kind | For number-like columns. |
